\subsection{Recorded environment and commands}
The execution report records Tamarin~1.12.0 and Maude~3.5.1 under WSL
Ubuntu~24.04, with the prover at
\path{/home/linuxbrew/.linuxbrew/bin/tamarin-prover}.
The recorded search path was
\path{/home/linuxbrew/.linuxbrew/bin:/usr/bin:/bin}.
The following equivalent shell sequence exposes that environment setting
once and preserves the six recorded program invocations. Run it from the
repository root in the recorded WSL environment; these are reproduction
instructions, not commands executed during manuscript preparation.

\begin{lstlisting}[style=modelcode]
export PATH=/home/linuxbrew/.linuxbrew/bin:/usr/bin:/bin

tamarin-prover --parse-only \
  tamarin/rq-v2-minimal/rqv2_relaxed.spthy
tamarin-prover --parse-only \
  tamarin/rq-v2-minimal/rqv2_message_dedup.spthy
tamarin-prover --parse-only \
  tamarin/rq-v2-minimal/rqv2_party_admission.spthy

tamarin-prover --prove \
  tamarin/rq-v2-minimal/rqv2_relaxed.spthy
tamarin-prover --prove \
  tamarin/rq-v2-minimal/rqv2_message_dedup.spthy
tamarin-prover --prove \
  tamarin/rq-v2-minimal/rqv2_party_admission.spthy
\end{lstlisting}

A reproduction should check the inputs before execution and compare each
model--lemma outcome with Table~\ref{tab:verification-results}. The recorded
proof-step counts are metadata, not runtime benchmarks or semantic parts
of the claims. To create new execution evidence, separately retain tool
versions, the execution commit and working-tree state, commands, exit codes,
stdout/stderr, and any exported traces, then hash the retained files. Such
a future run must be distinguished from the existing record.
