# K-Waay Core Protocol Object Map

## How to use this file

This file is not a final security conclusion. It is a working object map that decomposes the original K-Waay core protocol into objects for a first ProVerif symbolic model.

When reading the original K-Waay paper later, update each `CHECK` or `UNK` item to
`confirmed` only after the exact field, binding, or modeling assumption has been verified.

## Scope

- object of analysis: original K-Waay core protocol without full BatchReceive.
- tool target: first ProVerif symbolic model.
- primitive abstraction: signatures, long-term KEM, ephemeral KEM, split-KEM, and KDF are modeled as abstract cryptographic primitives.
- out of scope: deniability proof, Tamarin state model, CryptoVerif computational proof, Sparrow-KEM internal MLWE construction.

## Legend

- Y = yes / included
- N = no / not included
- CHECK = should be checked against the original K-Waay paper
- UNK = unknown / uncertain
- NA = not applicable

## Core Message Flow without Full BatchReceive

1. Setup / KeyGen
   - A and B each generate long-term signature key pairs.
   - A and B each generate long-term KEM key pairs.
   - Long-term public key pk = (spk, kpk); secret key sk = (ssk, ksk).
   - A and B publish long-term public verification and KEM keys through the assumed
     public infrastructure.
   - The server stores or serves public keys and prekey bundles according to the core
     protocol assumptions; trust model: check original paper.

2. InitSender(A)
   - A generates sender split-KEM prekey material with KeyGenA_sKEM.
   - A derives the corresponding sender split-KEM prekey public key.
   - A sets the sender ephemeral KEM public key field to bottom.
   - A signs (espki, ekpki) with A's long-term signature secret key ssk.
   - A constructs sender prekey bundle preki = (espki, bottom, sigma_i).
   - A uploads or makes available the signed sender prekey bundle.

3. InitReceiver(B)
   - B generates receiver split-KEM prekey material with KeyGenB_sKEM.
   - B derives the corresponding receiver split-KEM prekey public key.
   - B generates receiver ephemeral KEM secret material and the corresponding ephemeral
     public key.
   - B signs (espki, ekpki) with B's long-term signature secret key ssk.
   - B constructs receiver prekey bundle preki = (espki, ekpki, sigma_i).
   - B uploads or makes available the signed receiver prekey bundle.

4. Send(A,B)
   - A obtains B's receiver prekey bundle and verifies B's signature using B's
     long-term signature public key.
   - A selects or references A's sender prekey bundle for this session.
   - A encapsulates to B's long-term KEM public key to obtain the long-term KEM
     ciphertext and shared secret.
   - A encapsulates to B's receiver ephemeral KEM public key to obtain the ephemeral
     KEM ciphertext and shared secret.
   - A runs the split-KEM sender-side operation using A's sender split-KEM secret
     material and B's receiver split-KEM public material.
   - A forms message m = (ct_l, ct_k, ct_s).
   - A derives `sid` as Pi || Pj || pki || pkj || preki || prekj || m.
   - A derives the session key as KDF(K_l, K_k, K_s, sid).
   - A sends the network message tuple m with the receive context.

5. Receive(B,A)
   - B receives the network message tuple from the network or server.
   - B obtains A's sender prekey bundle and verifies A's signature using A's
     long-term signature public key.
   - B decapsulates the long-term KEM ciphertext using B's long-term KEM secret key.
   - B decapsulates the ephemeral KEM ciphertext using B's receiver ephemeral KEM secret key.
   - B runs the split-KEM receiver-side operation using B's receiver split-KEM secret
     material and A's sender split-KEM public material.
   - B reconstructs `sid` as Pj || Pi || pkj || pki || prekj || preki || mj.
   - B derives the session key as KDF(K_l, K_k, K_s, sid).
   - B accepts only if all required verification and decapsulation checks succeed;
     failure behavior: check original paper.

## BatchReceive Note for Later Tamarin Model

- Full batch abort is triggered by split-KEM decapsulation failure Ks = bottom.
- If K_l or K_k fails, that item outputs bottom, but Figure 7 only sets the
  global fail flag when Ks = bottom.
- This is not modeled in the first no-batch ProVerif core model.
