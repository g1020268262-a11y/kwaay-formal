# 批内性质依赖专项审查

## 1. 审查结论与证据类型

在当前三个固定两槽模型共同使用的规则和新鲜性假设下，对每条有效迹 `τ` 有：

\[
P_\tau\Rightarrow M_\tau,\qquad
M_\tau\Leftrightarrow I_\tau,\qquad
M_\tau\nRightarrow P_\tau.
\]

前两个关系是**基于现有 Tamarin 规则的人工迹语义推导**，本轮没有新增、运行或验证相应 lemma。第三个非蕴含由消息互异约束模型中的既有 lemma `same_party_different_messages_batch_exists` 给出直接的机器见证。现有 `accepted_batch_has_distinct_messages`、`receiver_accept_injective` 和 `accepted_batch_has_distinct_parties` 仍是三个不同公式、不同 lemma；模型内存在逻辑依赖不意味着这些 lemma 是同一个 lemma。

## 2. 迹级定义与量词范围

令 `Acc(A,oid,m,bid,rst)@r` 简写模型动作事实 `ReceiverAccept(A,oid,m,bid,rst)@r`。以下定义只比较一条迹 `τ` 中共享同一 `(bid,rst)` 的接受事件。

### 2.1 批内参与方互异性 `Pτ`

\[
\begin{aligned}
P_\tau \triangleq \forall&A_1,A_2,o_1,o_2,m_1,m_2,b,r,r_1,r_2.\\
&Acc(A_1,o_1,m_1,b,r)@r_1\in\tau\land
Acc(A_2,o_2,m_2,b,r)@r_2\in\tau\land r_1\neq r_2\\
&\Longrightarrow A_1\neq A_2.
\end{aligned}
\]

这与 `accepted_batch_has_distinct_parties` 的结论形状一致。

### 2.2 批内消息互异性 `Mτ`

\[
\begin{aligned}
M_\tau \triangleq \forall&A_1,A_2,o_1,o_2,m_1,m_2,b,r,r_1,r_2.\\
&Acc(A_1,o_1,m_1,b,r)@r_1\in\tau\land
Acc(A_2,o_2,m_2,b,r)@r_2\in\tau\land r_1\neq r_2\\
&\Longrightarrow m_1\neq m_2.
\end{aligned}
\]

这与 `accepted_batch_has_distinct_messages` 的结论形状一致。

### 2.3 批内来源单射性 `Iτ`

\[
\begin{aligned}
I_\tau \triangleq \forall&A,o,m,b,r,s,r_1,r_2.\\
&Send(A,o,m)@s\in\tau\land Acc(A,o,m,b,r)@r_1\in\tau\\
&\land Acc(A,o,m,b,r)@r_2\in\tau\land s<r_1\land s<r_2
\Longrightarrow r_1=r_2.
\end{aligned}
\]

这就是三个模型中 `receiver_accept_injective` 的量词和作用域。它不是 Lowe 意义下的完整认证单射一致性。

## 3. 推导所依赖的共同规则事实

三个模型的下列规则体相同，独立复核材料也确认七个共同规则在规范化空白后逐字一致。

1. **唯一发送产生规则。** `SendMessage` 是唯一产生 `Send(A,sid,m)` 和 `!Sent(A,sid,m)` 的规则。
2. **消息新鲜性。** 每次 `SendMessage` 都使用 `Fr(~m)`；因此两个 `Send` 事件若具有相同消息原子 `m`，它们只能是同一次规则实例化。
3. **发送实例标识新鲜性。** 每次 `SendMessage` 同时使用 `Fr(~sid)`。本节三个推导都不需要单独调用该条件，因为消息新鲜性已经唯一确定发送规则实例；它仍是当前模型的真实假设。
4. **精确来源匹配。** `ProcessSlot1` 和 `ProcessSlot2` 分别要求完整的 `!Sent(Ai,sidi,mi)`，随后发出参数完全匹配的 `ReceiverAccept(Ai,sidi,mi,bid,rst)`。
5. **先后关系。** `!Sent` 只能由更早的 `SendMessage` 产生，所以每个接受都有更早的完整元组匹配 `Send`。该事实也由三个模型各自的 `receiver_accept_has_send` 独立验证。
6. **共同批次坐标。** 两个处理步骤沿线性状态传递相同 `(bid,rst)`；本节只讨论该共同上下文内的事件。

模型位置：`rqv2_relaxed.spthy:17--27,58--72`、`rqv2_message_dedup.spthy:20--30,69--83`、`rqv2_party_admission.spthy:20--30,69--83`。

## 4. `Pτ ⇒ Mτ`

### 4.1 逐步推导

1. 固定任意 R/M/P 模型迹 `τ`，假设 `Pτ` 成立。
2. 反设 `Mτ` 不成立。则同一 `(bid,rst)` 中存在两个不同接受事件 `r1≠r2`，且 `m1=m2=m`。
3. 由两个处理规则的精确 `!Sent` 前提，每个接受分别具有更早的完整元组匹配发送：`Send(A1,o1,m)` 与 `Send(A2,o2,m)`。
4. 由于 `m` 由 `Fr(~m)` 产生且只有 `SendMessage` 发出 `Send`，两个相同 `m` 的发送必须是同一次规则实例化。因此 `A1=A2` 且 `o1=o2`。
5. 但 `Pτ` 对两个不同的同域接受要求 `A1≠A2`，产生矛盾。因此 `Mτ` 成立。

### 4.2 条件清单

| 检查项 | 结论 |
|---|---|
| 量词范围 | 单条迹内、同一 `(bid,rst)`、任意两个不同 `ReceiverAccept` 事件 |
| 使用消息新鲜性 | **是，关键条件** |
| 使用 `sid/oid` 新鲜性 | 否；当前规则虽具备，但相同新鲜消息已唯一确定发送实例 |
| 使用 `!Sent` 来源匹配 | **是，关键条件** |
| 是否适用于 R/M/P | 是，作为每条迹的条件蕴含；这不表示 R 或 M 模型在所有迹上满足 `Pτ` |
| 机器证明状态 | **未作为该方向的 Tamarin lemma 运行**；是人工语义推导 |
| 能否推广到真实 K-Waay | 不能直接推广；具体消息可重复、编码相等和接收来源关系未由本抽象精化 |

论文中最稳妥的表述：**“在当前三个模型共用的新鲜消息和精确来源匹配规则下，人工迹语义推导表明，批内参与方互异性蕴含批内消息互异性；该关系不是完整 K-Waay 的一般定理。”**

## 5. `Mτ ⇒ Iτ`

### 5.1 逐步推导

1. 固定任意迹 `τ`，假设 `Mτ` 成立。
2. 取 `Iτ` 前件中的任意 `Send(A,o,m)@s` 和两个同坐标接受事件 `r1,r2`。
3. 两个接受的消息分量都等于 `m`，批次与接收方上下文相同。
4. 若 `r1≠r2`，则直接违反 `Mτ`；因此只能有 `r1=r2`，即 `Iτ` 成立。

### 5.2 条件清单

| 检查项 | 结论 |
|---|---|
| 量词范围 | 单条迹内、同一 `(bid,rst)`、相同完整元组的两个接受 |
| 使用消息新鲜性 | 否 |
| 使用 `sid/oid` 新鲜性 | 否 |
| 使用 `!Sent` 来源匹配 | 否；`Iτ` 前件虽含 `Send`，但 `Mτ` 已仅凭相同消息排除两个不同接受 |
| 是否适用于 R/M/P | 是 |
| 机器证明状态 | **未作为蕴含 lemma 运行**；M 模型中 M 与 I 分别有独立机器结果 |
| 能否推广到真实 K-Waay | 只要采用完全相同的事件定义和批次作用域，该纯逻辑方向成立；当前模型事件尚未精化为完整协议事件，因此不能据此宣称完整协议定理 |

论文中最稳妥的表述：**“按本文两个迹性质的定义，批内消息互异性足以排除同一完整元组在同一批次上下文中的两次不同接受，因而蕴含本文定义的批内来源单射性。”**

## 6. `Iτ ⇒ Mτ`

### 6.1 逐步推导

1. 固定任意 R/M/P 模型迹 `τ`，假设 `Iτ` 成立。
2. 反设 `Mτ` 不成立：存在 `r1≠r2` 的两个同域接受，且二者消息相同为 `m`。
3. 由精确 `!Sent` 匹配，两个接受分别有更早的 `Send(A1,o1,m)` 与 `Send(A2,o2,m)`。
4. 由消息新鲜性和 `SendMessage` 的唯一产生关系，两发送是同一次事件，故 `A1=A2`、`o1=o2`，并可取同一个更早发送时间 `s`。
5. 此时 `Iτ` 的完整前件成立，应有 `r1=r2`，与反设矛盾。因此 `Mτ` 成立。

### 6.2 条件清单

| 检查项 | 结论 |
|---|---|
| 量词范围 | 单条迹内、同一 `(bid,rst)`、任意两个不同接受 |
| 使用消息新鲜性 | **是，关键条件** |
| 使用 `sid/oid` 新鲜性 | 否；不是本推导的独立必要条件 |
| 使用 `!Sent` 来源匹配 | **是，关键条件** |
| 是否适用于 R/M/P | 是 |
| 机器证明状态 | **未作为该方向的 Tamarin lemma 运行**；是人工语义推导 |
| 能否推广到真实 K-Waay | 不能直接推广；若不同发送可以具有相同消息，或接受不要求本文的精确来源事实，该方向可失效 |

论文中最稳妥的表述：**“反向关系依赖当前模型的消息新鲜性和精确来源匹配；在这些假设下，批内来源单射性与批内消息互异性在迹上等价。这不是任意协议中的一般等价关系。”**

## 7. `Mτ ⇏ Pτ`

### 7.1 机器反例形状

消息互异约束模型已验证 `same_party_different_messages_batch_exists`。其见证具有：

\[
\begin{gathered}
Send(A,o_1,m_1)@s_1,\quad Send(A,o_2,m_2)@s_2,\\
o_1\neq o_2,\quad m_1\neq m_2,\\
Acc(A,o_1,m_1,b,r)@r_1,\quad Acc(A,o_2,m_2,b,r)@r_2,\quad r_1\neq r_2.
\end{gathered}
\]

两个接受满足 `Mτ`，且各自只使用自己的匹配来源；在当前规则下也满足 `Iτ`。但两个参与方投影均为 `A`，所以 `Pτ` 失败。这是已运行的既有机器见证，不是本轮构造的新实验。

### 7.2 条件清单

| 检查项 | 结论 |
|---|---|
| 使用消息新鲜性 | 见证显式包含不同新鲜消息；非蕴含本身由已验证存在迹直接给出 |
| 使用 `sid/oid` 新鲜性 | 见证显式要求 `o1≠o2` |
| 使用 `!Sent` 来源匹配 | 是；两个处理步骤分别读取各自完整来源 |
| 适用模型 | 直接机器见证来自 M 模型；R 模型也允许该形状，P 模型由 `A1≠A2` 排除它 |
| 能否推广到真实 K-Waay | 只能作条件性接口解释；没有 witness lifting 或 refinement 证明其为完整 K-Waay 执行 |

论文中最稳妥的表述：**“消息互异约束模型存在一个同参与方、不同发送实例、不同消息且各有匹配来源的完整两槽可达执行；因此，在该抽象中，批内消息互异性不能推出批内参与方互异性。”**

## 8. 三模型中的适用方式

| 模型 | P | M | I | 依赖关系如何使用 |
|---|---|---|---|---|
| R：无互异约束 | 未作全称验证；重复同元组见证上失败 | 未作全称验证；同一见证上失败 | 机器结果 falsified | `M⇔I` 是规则层人工关系；已有见证同时使二者失败 |
| M：消息互异约束 | 被既有同参与方异消息见证反驳 | 机器 verified | 机器 verified | 两个机器结果均真实，但在共同规则下不是两项逻辑独立保证；`M⇔I` 为人工推导 |
| P：参与方互异约束 | 机器 verified | 未设置独立 lemma | 机器 verified | 由 `P⇒M` 可人工推出 M；I 仍有独立机器结果。不得把推导写成新增验证结果 |

## 9. 对论文论证的直接影响

当前论文说“两项 lemma 均验证通过”是事实；问题在于摘要、贡献和综合结果多次把 M 与 I 并列为共同支撑，容易让审稿人理解为两项独立保证。在当前规则下，I 没有为 M 模型提供独立于 M 的额外区分能力。机器结果不应删除，因为它们验证了不同公式并保留可追踪性；正文应增加一处依赖披露，并把非替代性的新信息明确归于 `same_party_different_messages_batch_exists` 的可达执行。

**审计结论：性质依赖可核实，无未决数学主张；但投稿前应以最小文字修订披露该依赖。**
