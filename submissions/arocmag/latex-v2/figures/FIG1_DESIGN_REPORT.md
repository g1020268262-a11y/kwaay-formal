- **七个主单元**：发送实例与候选条目暴露、攻击者可控组合、两槽顺序收集、批次准入、槽位1处理、槽位2处理、处理完成。原稿中分散的发送/暴露、两个收集槽和三个大动作框已合并或降为次级信息。

## 5. 逐元素科学映射

| 图中元素 | Tamarin规则、动作或事实 | 图示语义与边界 |
|---|---|---|
| 发送实例与候选条目暴露 | `SendMessage`；动作`Send(A,sid,m)`；输出`Out(<A,sid,m>)`；持久事实`!Sent(A,sid,m)` | 同一主单元内区分动作、网络输出和持久来源；`!Sent`不属于攻击者边界 |
| 候选条目组合（攻击者可控） | `CollectSlot1/2`的`In`可选择已有条目 | 攻击者可以选择、排列或重复已暴露条目，不能凭空制造`!Sent`来源 |
| 两槽顺序收集 | `CollectSlot1`：`OpenSlot1`到`OpenSlot2`；`CollectSlot2`：`OpenSlot2`到`Collected` | 保留固定两槽及严格收集顺序 |
| 无额外互异要求 | `AdmitRelaxedBatch` | 收集完成后可直接准入；该模型没有`RejectRepeated...`规则 |
| 消息互异约束$m_1\neq m_2$ | `AdmitDistinctMessages`；`Neq(m1,m2)` | 只比较消息分量 |
| 参与方互异约束$A_1\neq A_2$ | `AdmitDistinctParties`；`Neq(A1,A2)` | 只比较参与方分量 |
| 互异约束不满足后的拒绝 | `RejectRepeatedMessage`或`RejectRepeatedParty`；动作`Reject`；状态`BatchRejected` | 只属于消息互异约束模型和参与方互异约束模型 |
| 准入到槽位1处理的箭头动作 | `BatchReceive(bid,rst)` | 是准入规则产生的动作事实，不是独立处理状态 |
| 槽位1处理并匹配来源 | `ProcessSlot1`；前提`!Sent(A1,sid1,m1)` | 完整元组来源匹配后转入第二槽处理状态 |
| 槽位1到槽位2处理的箭头动作 | `ReceiverAccept(A1,sid1,m1,bid,rst)` | 是`ProcessSlot1`产生的动作事实 |
| 槽位2处理并匹配来源 | `ProcessSlot2`；前提`!Sent(A2,sid2,m2)` | 完整元组来源匹配后进入完成状态 |
| 槽位2到完成的箭头动作 | `ReceiverAccept(A2,sid2,m2,bid,rst)` | 是`ProcessSlot2`产生的动作事实 |
| 处理完成 | `BatchComplete(bid,rst)` | 规则右侧的终止状态事实，不是动作事实 |

图中的`ReceiverAccept(E_i,bid,rst)`只是以已定义的$E_i=(A_i,\mathit{oid}_i,m_i)$压缩显示真实五元动作参数，未修改模型签名或科学含义。正文中的$\mathit{oid}$对应Tamarin模型中的`sid`。

## 7. 第一次人工审查后的修订

1. **限定Reject范围。** 三个源模型中，只有消息互异约束模型含`RejectRepeatedMessage`，参与方互异约束模型含`RejectRepeatedParty`；无互异约束模型只有`AdmitRelaxedBatch`，因此拒绝框明确限定为前两类约束模型。
2. **重分配BatchReceive的视觉层。** `BatchReceive`由准入规则在从`Collected`转入`AdmittedSlot1`时产生，故改为准入到槽位1处理之间的动作标签。
3. **重分配ReceiverAccept的视觉层。** 两个`ReceiverAccept`分别由`ProcessSlot1`和`ProcessSlot2`产生，故改为处理阶段之间的动作标签，不再画成独立状态节点。
4. **压缩视觉层级。** 原来的约11个同权大框压缩为7个主单元，使“批次准入（受控变化）”成为唯一强调区域。
5. **保持科学语义。** 修订没有删除两槽收集顺序、三个动作事实、完整元组来源匹配、三种准入条件、两类拒绝分支或完成状态，也没有合并为更强的认证性质。
6. **贴近P1/P2图式。** 主轴由状态/处理阶段构成，动作放在转移上，局部受控变化以浅灰模块突出，因而比同权步骤框串联更接近形式化状态图和论文方法框架，减少了通用软件流程图观感。
