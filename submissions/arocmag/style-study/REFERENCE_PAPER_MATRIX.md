# 《计算机应用研究》同类论文结构矩阵

## 1. 样本与证据口径

本矩阵以 7 篇《计算机应用研究》正式发表论文为样本。所有论文均从期刊官网的“正式出版”入口取得 `version=v2` PDF，并逐页检查了章节、二级标题、公式、图表、结果和结束语。7 篇均为全文证据，未出现 `FULL_TEXT_NOT_AVAILABLE`。

统计中的“独立”分为两层：

- “独立一级章”指与“协议设计”“安全性分析”平级的一级标题；
- “独立小节”指有明确标题，但仍嵌在预备知识、模型或安全性分析内部。

因此，“存在攻击者模型小节”不等于该刊习惯单设一个 Threat Model 一级章。

## 4. 章节矩阵

### P1　基于 Tamarin 的 MQTT 协议安全性分析方法

- **一级结构**：0 引言；1 MQTT 协议概述；2 MQTT 协议形式化建模；3 验证及结果分析；4 基于身份重认证的优化方案；5 结束语。
- **二级结构**：1.1 对象模型，1.2 交互过程；2.1 状态机建模，2.2 安全属性建模，2.3 攻击者建模；3.1 保密属性结果，3.2 认证属性结果，3.3 分析结果验证。
- **安全属性位置**：形式化模型章内部，且在攻击者模型之前；认证与保密分别定义。
- **结果解释位置**：第 3 章按“保密性质—认证性质—外部验证”解释，表格汇总后选择典型失败作语义说明。
- **图表功能**：对象/交互、状态机、Tamarin 结果、验证环境和优化协议图；表格承担性质清单、机器结果和验证结果汇总。
- **特殊性**：第 4 章提出优化方案，是该文“发现问题后给改进”的研究任务所致，不宜视为所有 Tamarin 论文的固定章。

### P2　基于安全协议代码的形式化辅助建模研究

- **一级结构**：0 引言；1 基本理论；2 基于污点分析的信息提取；3 协议通信状态机构建；4 形式化模型生成；5 实验案例与分析；6 结束语。
- **二级结构**：1.1 污点分析，1.2 Tamarin 模型；2.1 消息传递流程提取，2.2 密码学原语提取；5.1 实验设计与实现，5.2 案例分析，5.3 实验结果与分析。
- **安全属性位置**：不是核心组织轴；论文主线是“代码—信息提取—状态机—Tamarin 模型”。
- **结果解释位置**：案例与实验章，用模型度量表和比例图说明生成质量与工作量。
- **图表功能**：框架、污点流程、有限状态机、转换过程、代码片段、工具结果和指标比例。
- **特殊性**：方法流水线被拆成多个一级章，源于“辅助建模方法”这一研究对象；不能直接移植到 K-Waay 的协议语义分析。

### P3　可证明安全的后量子两方口令认证密钥协商协议

- **一级结构**：0 引言；1 预备知识；2 基于 RLWE 的 PAKA 方案设计；3 安全分析；4 结束语。
- **二级结构**：1.1 基于格的难题假设（含 RLWE 和数学背景），1.2 格上离散高斯分布，1.3 BPR 安全模型（协议模型、敌手模型）；2.1 初始化，2.2 注册，2.3 认证，2.4 口令更新，2.5 正确性证明；3.1 形式化证明，3.2 安全性分析，3.3 性能分析。
- **安全属性位置**：先在 BPR 模型中给实验、查询与优势定义，协议描述后再给定理和游戏序列。
- **结果解释位置**：安全证明结束后给非形式化性质和性能比较。
- **图表功能**：三幅协议流程图；表格承担符号、运行时间、计算、通信及综合比较。
- **公式特征**：预备知识和证明高度数学化，定义、引理、定理与编号公式集中出现。

### P4　无线传感器网络中基于 PUF 的轻量级多网关身份认证协议

- **一级结构**：0 引言；1 基础知识；2 相关描述；3 提出的协议；4 安全性分析；5 对比分析；6 结束语。
- **二级结构**：2.1 协议框架，2.2 应用场景，2.3 协议优点；3.1～3.6 依次为初始化、用户注册、传感器注册、登录认证与密钥协商、口令更新、注销；4.1 ROR 证明，4.2 ProVerif，4.3 非形式化安全分析；5.1 计算，5.2 存储，5.3 安全性比较。
- **安全属性位置**：协议完整描述之后，在安全性分析章内按“ROR—ProVerif—逐项安全性”组织。
- **结果解释位置**：ProVerif 截图后简述查询结果；性能章以图表比较后给优势结论。
- **图表功能**：网络结构、协议各阶段流程、ProVerif 结果、计算/存储/通信柱状图。
- **特殊性**：11 幅图反映其协议阶段多且性能比较多，并不代表形式化论文应追求高图量。

## 5. 共同模式与不应误归纳的部分

### 稳定模式

1. 一级章通常为 5～7 个；研究任务复杂时可到 8 个，但每章目的单一。
2. 相关工作多在引言中压缩完成；只有综述负担较重时才单列。
3. 威胁模型经常是预备知识、系统模型或形式化分析中的小节，没有样本把它设为独立一级章。
4. 安全性质在模型或安全分析开始处定义，机器结果随后出现。
5. 结果表承担压缩功能，正文解释代表性成功、失败及其安全含义。
6. Discussion 和 Limitations 不单列；解释和边界分散在结果分析、结束语或相关论证结尾。

### 内容驱动的特殊结构

- P1 的“优化方案”来自发现漏洞后的修正任务。
- P2 把建模流水线拆章，是方法生成论文的需要。
- P4/P5/P6 的多阶段协议流程和性能图表来自认证协议设计，不适合机械移植到 K-Waay 的语义分析。
- P3/P7 的高公式密度来自格密码与 ROR 证明，不代表 Tamarin 论文也应保持同等数学密度。
