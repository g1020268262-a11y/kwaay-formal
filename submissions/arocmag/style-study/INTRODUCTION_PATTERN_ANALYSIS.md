# 引言叙事模式分析

## 1. 编码方法

对 7 篇全文的引言按六个修辞动作编码：

- **M1 背景与重要性**：建立场景、应用或安全问题的重要性；
- **M2 现有工作**：概括同类协议、工具或方法；
- **M3 问题与不足**：指出攻击、效率、建模成本或语义缺口；
- **M4 本文方法**：提出协议、模型、工具链或分析方案；
- **M5 主要结果/优势**：报告安全、性能、自动化或验证结论；
- **M6 贡献/结构**：列出本文工作或安排。

编码只记录论文实际承担的功能，不把某个固定句式当成强制格式。

## 2. 逐篇动作序列

| 论文 | 主要序列 | 引言末段形态 | Related Work 位置 |
|---|---|---|---|
| P1 Tamarin-MQTT | M1 → M2 → M3 → M4 → M5 | 用“针对……”提出 Tamarin 方法并概述结果 | 引言集中完成 |
| P2 形式化辅助建模 | M1 → M2 → M3 → M4 → M5 | 从人工建模成本转向辅助建模流程和实验 | 引言集中完成 |
| P3 后量子 PAKA | M1 → M2 → M3 → M4 → M5 | 提出 RLWE 方案并概括安全与效率 | 引言集中完成 |
| P4 PUF 多网关 | M1 → M2 → M3 → M4 → M6 | 明确写“本文主要工作如下”，列 a)～d) | 引言集中完成 |
| P5 PUF 医疗多网关 | M1 → M3 → M4 → M6 | 列两项主要贡献；文献回顾后移到第 1 章 | 独立第 1 章 |
| P6 智能电网认证 | M1 → M3 → M4 → M6 | 明确列 a)～d)：攻击、方案、证明、比较 | 独立第 1 章 |
| P7 格上多因素 AKE | M1 → M2 → M3 → M4 → M5/M6 | “具体贡献如下”列三项并给安全/实验结论 | 引言集中完成 |

所有样本都包含 M1、M3 和 M4。M2 在 5 篇引言内承担主要文献回顾，另 2 篇把详细回顾放入独立“相关工作”。M5 与 M6 经常合并：贡献条目同时告诉读者采用了什么方法、得到什么安全或性能结果。

## 3. 稳定节奏

### 3.1 开头先建立应用或接口问题

样本不会在首段立即给复杂定义。常见开法是：

1. 交代 MQTT、智能电网、无线传感器网络、口令认证或多因素认证的用途；
2. 引出开放网络、量子攻击、资源受限或人工建模的风险；
3. 再缩小到本文要解决的协议或建模对象。

K-Waay 中文稿宜先说明“一次接收操作组合多个发送方关联输入”为什么使批内关系成为独立安全问题，再介绍三个形式化变体。这样主线是协议接口问题，模型是回答问题的方法。

### 3.2 相关工作通常压入引言中部

5/7 样本在引言中完成主要 related work。常见组织是按问题链而不是按作者逐篇罗列：已有协议或验证工作解决了哪些问题，仍留下什么缺口，然后导向本文。只有 P5 和 P6 因同类认证方案及漏洞脉络较长而单设“相关工作”。

K-Waay 现稿的 Related Work 约 1,200 个英文词，分为五个小节；若整体保留为独立章，会显著慢于样本。中文稿应在引言中压缩为三组证据：K-Waay 与异步密钥交换、组合层形式化分析、身份/注入性语义。只保留定位贡献所需的差异，不重复完整文献综述。

### 3.3 问题陈述短而直接

样本频繁使用“针对上述问题”“为解决……”“本文提出/采用……”完成 M3→M4 转折。它们的功能是把综述快速收束到研究动作。典型段落通常只完成三件事：指出缺口、给方法、给评价维度。

K-Waay 不必模仿固定措辞，但应采用同样的压缩逻辑：

> K-Waay 已明确要求同一 BatchReceive 调用中的输入来自不同参与方，但该条件维持的身份关系以及其他坐标约束能否替代它，尚缺少形式化比较。为此，本文构建共享生命周期的三个两槽 Tamarin 模型……

这一表达同时保留来源边界和研究缺口，避免把原协议的既有条件误写成本文发现的漏洞。

### 3.4 贡献通常落在引言末端

P4、P5、P6、P7 明确列出 2～4 项工作；P1～P3 也在末段集中交代方法和结果，只是未必使用编号列表。贡献项短、动作明确，并常同时含有结果：提出/构建什么，证明/验证什么，与什么比较。

K-Waay 适合保留三项贡献：

1. 从 BatchReceive 的既有不同参与方条件中抽取批内参与方不变量，并区分参与方、消息和发送发生坐标；
2. 在相同两槽生命周期上构建放宽、消息级和参与方级三个受控变体；
3. 通过记录的 Tamarin 结果说明消息不同和作用域内发生注入性不推出批内参与方不同，并给出非空的参与方级对照。

### 3.5 篇幅

按正式 PDF 版面估算，引言通常约占 0.8～1.4 个排版页；相对于 6～9 页正文，约为 12%～20%。独立相关工作的两篇，引言本身更短，但“引言+相关工作”的总量仍受控。该比例是样本观察，不是版面规则。

对 K-Waay，建议中文引言约占全文 12%～15%。应容纳背景、紧凑相关工作、问题、方法、结果和贡献，不在引言展开所有模型限制。

## 4. Scope/Non-goals 的处理

样本很少像英文安全论文那样在引言设置较长的 scope/non-goals 段。边界通常通过以下三种方式表达：

1. 在首次给出模型或结果时限定其对象，例如“在该模型下”“针对所述协议”；
2. 在结果解释末尾说明结论只覆盖哪些攻击或性质；
3. 在结束语用一句话提出仍需研究的内容。

K-Waay 当前引言的 Scope 段同时列出组合控制、固定两槽、理想源关系、非完整协议、非部署漏洞、无原始记录等多项限制。中文稿宜只在引言保留一句总边界：本文分析固定两槽的批准入抽象，结论止于模型中的接收事件。其余限制分别放在首次相关结果和“4.3 适用范围与局限”，避免每节重复。

## 5. 推荐的 K-Waay 引言内部顺序

1. **M1**：异步密钥交换中的批接收及组合关系重要性；
2. **M2**：K-Waay、组合层形式化分析、身份与注入性工作，压缩为 2～3 段；
3. **M3**：既有不同参与方条件的语义作用及坐标替代问题尚未被比较；
4. **M4**：三个共享生命周期的两槽 Tamarin 变体；
5. **M5**：放宽模型反例、消息级对照、参与方级恢复；
6. **M6**：三项贡献；最后用一句话交代文章结构。

不建议在引言中重复完整 RQ1/RQ2/RQ3、逐项 non-goal、模型文件细节或 14 条 lemma 名称。
