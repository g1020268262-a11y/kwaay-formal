# 结果章节叙事分析

## 1. 样本中的结果组织

| 类型 | 典型顺序 | 代表样本 |
|---|---|---|
| Tamarin 协议分析 | 性质分组 → 工具结果表/轨迹 → 代表性失败解释 → 外部验证或改进 | P1 |
| 形式化建模方法 | 实验设计 → 案例 → 模型指标/图表 → 方法效果解释 | P2 |
| ROR/BPR 协议 | 安全定义 → 定理/游戏证明 → 攻击抵抗 → 性能比较 | P3～P7 |
| ProVerif 辅助验证 | 查询/场景 → 结果截图 → 机密性和认证含义 | P4～P6 |

形式化论文的稳定内核是“对象或性质 → 机器/数学结果 → 安全含义”，而不是简单罗列工具输出。

## 2. verified / falsified / attack trace 的表述

样本倾向把工具结论和论文结论分开：先说明某查询或性质的结果，再解释这意味着哪类攻击或安全保证。对 K-Waay，应保持以下层次：

- **存在性性质 verified**：表示在给定模型中找到满足公式的轨迹；它可以是正常可达性，也可以是攻击/反例见证。
- **全迹性质 verified**：表示记录的分析在该模型和假设下未找到反例并完成证明；只覆盖公式表达的边界。
- **全迹性质 falsified / counterexample found**：表示找到违反该公式的轨迹；应说明被推翻的是哪一项精确性质。
- **attack trace / witness**：描述事件顺序和坐标关系；不能自动扩展为完整 K-Waay 攻击、密码学破坏或部署漏洞。

由于本项目依赖既有执行记录，中文稿应使用“记录结果为……”“在记录的执行中……”；不能写成“本文重新运行证明了……”。

## 3. 是否逐条解释所有性质

不需要。P1 即使有较多安全属性，也通过表格汇总，正文只解释典型失败和关键验证。ProVerif 论文对相同含义的查询合并解释。性能论文也不会逐个数字复述表格。

K-Waay 的 14 条结果应完整列入主表，但正文围绕三条证据链：

1. relaxed：正常路径可达；一个发送源支持两个接收发生；发生注入性被反例推翻；源对应仍成立；
2. message-level：相同消息拒绝分支可达；消息不同与作用域内发生注入性成立；同一参与方的不同消息仍可同批到达；
3. party-level：规则直接约束参与方；接收边界的参与方不同性成立；有效不同参与方批次仍可达。

`receiver_accept_has_send` 等重复出现的支持性质在表中列全，正文可合并为一句。

## 4. 表后应写多少文字

样本通常在表/图后写一个到数个短段，完成三件事：指出最重要差异、解释其机制、给出对安全或性能的含义。K-Waay 的验证汇总表后建议写 3～4 段：

1. 解释表中“存在性”和“全迹”两类结果不能互换；
2. 提炼 relaxed 与 message-level 的差异；
3. 提炼 message-level 与 party-level 的差异；
4. 用一句集中边界收束，不重复全部 limitation。

## 5. 从机器结果到安全含义

推荐每个关键结果使用同一四步结构：

1. **性质**：它在模型中问什么；
2. **结果**：记录为 verified 还是 falsified；
3. **见证/机制**：哪些事件和坐标导致该结果；
4. **含义与边界**：它回答哪个研究问题，同时不回答什么。

例如 relaxed 结果应写成：存在性 lemma 找到一个精确发送源、一个批准入事件和两个同坐标接收事件；发生注入性性质因此被反例推翻；这说明放宽准入在两槽抽象中允许重复发生，但不等于完整协议认证失败。

message-level 的安全含义不是“修复失败”，而是“它成功维护消息坐标和精确发生关系，却不维护参与方坐标”。这种正反并列是论文的中心贡献。

## 6. Results 与 Discussion 的分工

样本没有独立 Discussion，但 K-Waay 的语义和证据边界需要一定解释。推荐分工如下：

- **结果章**：模型内可核查事实、轨迹、全迹性质、可达性和直接非蕴含；
- **讨论章**：为什么坐标不能替代、组合不变量与执行机制的区别、由谁维护关系、固定两槽和抽象端点的限制。

不要在讨论章重新叙述 14 条结果，也不要在结果章提前讨论所有可能部署架构。

## 7. K-Waay 结果章的推荐顺序

### 3.1 放宽准入的重复发生反例

先报告正常路径非空，再报告存在性见证和发生注入性反例，用轨迹图解释。段尾明确：这是放宽模型的接收事件反例，不是保留原条件的 K-Waay 执行。

### 3.2 消息级限制的对照结果

先确认消息重复拒绝和消息不同性成立，再给同一参与方、不同消息的可达轨迹。段尾形成中心判断：消息不同和作用域内发生注入性不推出批内参与方不同。

### 3.3 参与方级约束的恢复结果

依次写规则语义、全迹安全和有效批次可达性。三类证据分别回答“如何约束、是否维持、是否非空”。

### 3.4 结果汇总与语义解释

给完整结果表，合并重复支持性质，比较三种坐标。最后把模型从论文主角退回到方法位置：三个变体共同回答哪一种身份关系是目标不变量。
