# 3 K-Waay 消息篡改与重放攻击的形式化分析及加固

## 3.1 消息篡改攻击的发现

针对 K-Waay 核心密钥交换过程中发送方与接收方的会话一致性问题，本文利用 ProVerif 对原始协议的消息处理和密钥派生过程进行形式化分析，发现了一条能够诱导接收方接受篡改消息并产生会话参数失配的攻击路径。

在该攻击中，攻击者无需获得发送方或接收方的长期秘密密钥，也无需破解 KEM 或 split-KEM 算法，而是利用公开密钥重新构造协议消息中的部分密文分量。接收方收到篡改后的消息后，仍能够完成预密钥验证、密文解封装和会话密钥派生，并触发接收完成事件。然而，由于接收方处理的完整消息已经发生变化，其导出的会话标识及会话密钥与原发送方不一致，导致双方会话参数失配。

形式化验证表明，原始核心模型中的会话密钥机密性和 split-KEM 分量来源性质成立，但接收方与发送方的完整参数对应关系不成立。这说明**即使攻击者无法获得会话密钥，仍可能通过修改协议消息破坏双方的会话一致性**。

## 3.2 密文重组攻击过程与形成原因

设合法发送方为 A，接收方为 B。根据第1章介绍的协议过程，发送方执行三组密钥封装，产生共享秘密 K_l、K_k、K_s 及对应密文。原始发送消息为：

`m_A = (ct_l, ct_k, ct_s)`

发送方根据完整消息及身份、公钥和预密钥材料计算会话标识 sid_A，并派生会话密钥：

`k_A = KDF(K_l, K_k, K_s, sid_A)`

攻击者截获消息 m_A 后，通过以下过程构造攻击消息。

**（1）保留合法 split-KEM 分量。** 攻击者取得公开传输的密文元组，保留其中的 ct_s。该分量由合法发送方利用其 split-KEM 秘密材料产生，攻击者无法计算其对应的共享秘密 K_s。

**（2）重新构造普通 KEM 密文。** 由于接收方长期 KEM 公钥和临时 KEM 公钥均为公开材料，攻击者可以分别执行封装操作，生成新的 ct_l' 和 ct_k'，以及对应的共享秘密 K_l' 和 K_k'。这一过程不需要接收方秘密密钥。

**（3）组合并投递篡改消息。** 攻击者将新生成的普通 KEM 密文与保留的合法 split-KEM 分量组合，得到：

`m_B' = (ct_l', ct_k', ct_s)`

随后将 m_B' 投递给接收方 B，替代原始消息。

**（4）接收方处理篡改消息。** 接收方验证发送方预密钥签名后，分别对三个密文分量执行解封装。由于各分量均能够通过对应的局部密码学处理，接收方获得 K_l'、K_k' 和 K_s，并计算：

`sid_B' = SID(A, B, pk_A, pk_B, prekey_A, prekey_B, m_B')`

`k_B' = KDF(K_l', K_k', K_s, sid_B')`

**（5）接收方完成失配会话。** 原始接收流程在成功解封装和密钥派生后记录接收完成事件。由于发送方与接收方使用的完整消息不同，在本文符号模型中满足：

`m_A ≠ m_B'，sid_A ≠ sid_B'，k_A ≠ k_B'`

因此，发送方 A 与接收方 B 得到不同的会话参数，但 B 仍完成了接收过程。

**【图2插入位置：K-Waay 密文重组攻击流程】**

该攻击成功的原因在于，原始核心接收流程缺少对完整消息及其派生会话参数的显式确认。预密钥签名认证的是预先发布的密钥材料，而非随后传输的完整密文元组；split-KEM 提供的来源约束也不能阻止攻击者重新生成其他 KEM 密文。

虽然攻击者能够自行生成 K_l' 和 K_k'，但无法根据公开的 ct_s 推导 K_s，因而不能计算接收方最终派生的 k_B'。这与 ProVerif 中接收方会话密钥机密性成立的结果一致。

综上，密文重组攻击揭示了 K-Waay 接收端的一个重要安全问题：**局部密码分量合法以及会话密钥未泄露，并不能保证发送方和接收方的完整会话参数一致。**

## 3.3 HMAC 密钥确认机制及形式化验证

针对上述问题，本文在保留原有 KEM、split-KEM 封装及密钥派生结构的基础上，引入基于 HMAC 的显式密钥确认机制，使接收方在正式接受消息前验证完整会话参数的一致性。

发送方完成原协议的密钥派生后，从会话密钥 k_A 导出确认密钥，并生成确认标签：

`tag_A = HMAC(confirm_key(k_A), sid_A)`

其中，sid_A 绑定了参与方身份、公钥、预密钥材料及完整密文消息。发送方最终传输：

`M_A = (m_A, tag_A)`

接收方收到确认消息后，先执行原有预密钥签名验证、密文解封装及密钥派生，得到本地参数 sid_B 和 k_B，再计算：

`tag_B = HMAC(confirm_key(k_B), sid_B)`

仅当 `tag_B = tag_A` 时，接收方才完成正式接受；否则拒绝当前确认结果。

对于第3.2节中的攻击，由于攻击者重新构造了 ct_l' 和 ct_k'，接收方计算得到的 sid_B' 和 k_B' 与合法发送方不同。因此，原发送方生成的确认标签无法通过接收方针对篡改消息执行的校验。在无密钥泄露的符号模型中，攻击者也无法构造与该失配会话参数匹配的有效确认标签。

为验证修复效果，本文对原始核心模型和 HMAC 加固模型进行了 ProVerif 对比分析，结果如表2所示。

**表2 原始模型与 HMAC 加固模型的验证结果**

| 安全性质 | 原始模型 | HMAC 加固模型 |
| --- | --- | --- |
| 发送方会话密钥机密性 | 成立 | 成立 |
| 接收方会话密钥机密性 | 成立 | 成立 |
| split-KEM 分量来源性质 | 成立 | 成立 |
| 完整参数对应关系 P1 | 不成立 | 成立 |
| 正常执行可达性 | 可达 | 可达 |

注：结果对应无密钥泄露的符号配置；分量来源性质通过相应的独立检查配置验证。

原始模型中，ProVerif 找到了接收完成事件缺少相同会话参数发送完成事件的反例。加入 HMAC 确认后，完整参数对应关系由不成立转为成立，且会话密钥机密性和正常执行能力仍得到验证。

需要说明的是，原始模型与加固模型分别依据基础消息和确认消息的发送过程设置发送完成观察点，因此对应关系验证应结合各自事件定义理解。

上述结果表明，HMAC 确认机制能够在所验证的无泄露条件下阻断密文重组导致的失配接受路径。

## 3.4 HMAC 确认后的批内重放攻击

HMAC 能够确认接收方使用的会话参数与合法发送方一致，但不能保证同一合法消息在批次中仅被接受一次。

为分析这一问题，本文使用 Tamarin 建立固定两槽的 BatchReceive 模型，考察原协议参与方互异前置条件未被维持时的接收行为。

设发送方 A 生成合法确认消息：

`M = (m, tag)`

其中：

`tag = HMAC(confirm_key(k), sid)`

攻击者获得 M 后，不修改密文，也不伪造 HMAC，而是将其重复投递至接收方 B 的同一批次中两个不同槽位 idx₁ 和 idx₂。两个槽位共享批次标识 bid 和接收状态 rst。

由于两个槽位接收到的是完全相同的合法确认消息，因此分别通过确认检查，产生两个不同的成功接收事件。

这一过程形成：

**一次合法发送 → 两次成功接收**

**【图3插入位置：K-Waay 批内重复接受与条件化安全影响示意】**

Tamarin 验证表明，一次合法确认发送对应两次成功接收的攻击路径可达，接收单射性及同一消息至多接受一次的性质均不成立，而接收事件仍具有匹配的发送来源。

进一步分析表明，当上层组件在批次完成后逐项独立消费成功接收输出，且不对相同会话参数进行合并时，重复接收还可能形成多个独立安装事件。该结果来自独立的条件化消费模型，不代表实际实现必然发生重复安装。

上述结果说明，**HMAC 密钥确认能够阻断失配会话的接受，却不能单独限制合法消息在同一批次中的重复接受。**

## 3.5 批内原子去重与组合加固

针对密文重组和批内重复接受两类问题，本文进一步将 HMAC 密钥确认与批内原子消息去重相结合，提出消息级组合加固方案。

其中，HMAC 负责验证发送与接收会话参数的一致性，原子消息去重负责阻止同一完整消息在同一批次中被重复接受。

具体而言，接收方在完成批次收集和封闭后、处理任何槽位之前，统一检查批内基础消息：

`m = (ct_l, ct_k, ct_s)`

对于不同槽位 i、j，若满足：

`i ≠ j 且 m_i = m_j`

则判定存在重复消息，直接拒绝整个批次，不产生成功接收事件。若消息不同，则允许进入后续的密文解封装、密钥派生和 HMAC 确认流程。

去重机制比较的是完整基础消息 m，而非包含标签的 `(m, tag)`。因此，即使相同消息携带不同标签，也不能绕过去重检查。

为保证决策的原子性，模型采用一次性线性状态约束，使每个批次只能执行一次去重判定，避免在重复检查完成前产生成功接收事件。

**【图4插入位置：K-Waay 消息级组合加固后的发送与批量接收流程】**

图4建议沿用图1的协议流程，在原有步骤上以加粗或虚线框标出三处变化：发送方生成 HMAC 确认标签、接收方在处理槽位前执行批内原子去重，以及接收方在成功接受前验证 HMAC。

形式化验证结果表明，加入原子去重后，原先可达的重复接受攻击被阻断，批内消息接收单射性成立；在指定的上层消费条件下，重复安装路径也不再可达。同时，两个不同且有效的消息仍能够完成正常批次处理。

组合模型进一步验证了合法确认消息的重复接受受到阻断，同一基础消息携带不同标签时仍会触发重复拒绝，而正常的不同消息批次及后续消费保持可达。

因此，HMAC 与原子去重分别从**会话参数一致性**和**批内消息唯一性**两个方面提供防护，在相应的形式化模型中阻断了上述攻击路径。

需要指出的是，消息互异不等于参与方互异。同一参与方仍可能产生两个不同的合法消息，因此消息级去重不能替代 K-Waay 原协议的批内参与方互异前置条件。

## 3.6 本章小结

本章通过 ProVerif 和 Tamarin 分析了 K-Waay 接收端的消息篡改与批内重放问题。针对密文重组导致的会话参数失配，提出 HMAC 密钥确认机制；针对合法消息的批内重复接受，提出原子消息去重机制，并验证了两种机制的组合加固效果。

上述研究解决的是会话参数确认与相同消息重复接受问题，但不能保证同一批次内不同消息一定来自不同参与方。下一章将进一步围绕 K-Waay 原协议的 `DistinctPartyPerBatch` 前置条件，分析该条件未被维持时的批次身份语义及其安全影响。
